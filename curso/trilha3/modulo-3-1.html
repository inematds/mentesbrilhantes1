📱 Cal AI: Foto → Calorias. Só Isso.

A versão 1 do Cal AI fazia UMA coisa só. Aperta um botão, tira foto, mostra calorias. Sem dashboard, sem feed social, sem comparação com amigos, sem gráficos, sem login social, sem nada. Só o core.

3 passos. 5 segundos. Sem fricção.

⚡ Por que isso virou US$ 100M

Usuário não precisa pensar. Não precisa configurar. Não precisa criar conta antes. A barreira de entrada é praticamente zero.

Streaks, dashboards e gamificação só vieram depois, quando os dados de uso real disseram exatamente o que valia.

2

🎚️ Por Que 50 Features Matam

Você imagina que mais features = mais valor. Errado. Para o usuário, mais features = mais decisões a tomar = mais fricção = menos uso.

📊 O que acontece quando o app tem muita feature

  • • Tempo de aprendizado aumenta: usuário precisa entender 50 botões antes de extrair valor
  • • Bug surface aumenta: mais código = mais bugs = mais suporte
  • • Custo de manutenção explode: cada feature precisa ser atualizada para sempre
  • • Mensagem de marketing fica vaga: "faz tudo" = "faz nada bem"
3

✂️ A Pergunta-Corte

Quando estiver com a lista de features que você "precisa" ter, faça essa pergunta brutal: "Se eu cortar 80% dessas features, o produto ainda resolve a dor central?" Se sim, corte. Se não, ajuste a função-mãe até resolver.

🎯 Como aplicar

  1. Liste TODAS as features que você imaginou (vá fundo, sem censura)
  2. Marque a função-mãe — a UMA que resolve a dor central
  3. Para cada outra feature, pergunte: "sem ela, o usuário ainda resolve a dor?" Se sim, corta para versão 2.
  4. Sobra: 1-2 features. Essas é o seu MVP.

💡 Exemplo concreto

Imagina que você ia construir um app de fitness. Lista inicial: tracking, dashboards, planos, comunidade, vídeos, IA coach, comparação com amigos, gamificação...

Pergunta-corte aplicada: "se sumir tudo, exceto tracking, ainda resolve?" Sim. Tracking é a função-mãe. Comece com isso. Resto, depois.

4

🚫 Lista de Exclusão

Tão importante quanto saber o que ENTRA é documentar o que NÃO entra. Sem lista de exclusão, toda semana você vai pensar "ah, seria bom ter X" — e vai adicionando até virar canivete-suíço.

✓ Versão 1 (entra)

  • • Função-mãe: faz a coisa principal
  • • Login simples (e-mail/senha)
  • • Pagamento (se for pago)
  • • Mensagem de erro básica

✗ Versão 1 (NÃO entra)

  • • Login social (Google, Apple)
  • • Dashboard com gráficos
  • • Modo escuro
  • • Multi-idioma
  • • Notificações push
  • • Compartilhamento social
  • • Programa de indicação
  • • Onboarding guiado

⚡ Truque psicológico

A lista de exclusão é seu antídoto. Toda vez que pensar em adicionar algo, abra a lista. Se está lá, NÃO adiciona. A lista te protege de você mesmo.

5

⚰️ Casos Negativos: Produtos Inchados

Empresas grandes morrem por inchar. Você, sem recurso, morre 10x mais rápido. Aqui estão alguns casos famosos.

🪦 Google+

Tentou ser Facebook + Twitter + Instagram + Google Hangouts ao mesmo tempo. Resultado: faltou identidade clara. Morreu.

🪦 Microsoft Zune

Adicionou tudo que iPod não tinha — virou complicado. Pessoas queriam o iPod simples, não o Zune complexo.

🪦 BlackBerry Storm

Tela tátil + teclado físico + features corporativas. Confusão. iPhone, simples, dominou.

📊 O padrão

Em todos os casos, o vencedor tinha MENOS features mas mais clareza. Apple, Twitter, WhatsApp — todos venceram sendo bisturis enquanto concorrentes eram canivetes-suíços.

6

📝 Compromisso: Assina Sua Versão Minimalista

Última proteção contra o canivete-suíço: documente em 1 página, com sua assinatura, qual é a função-mãe e a lista de exclusão. Fixa na parede. Vira ritual.

📋 Template de compromisso

Produto: [nome]

Função-mãe (entra na v1): [a UMA coisa]

Para quem: [público específico]

Lista de exclusão (NÃO entra na v1):

- [feature X]

- [feature Y]

- [feature Z]

Data de lançamento (compromisso): [30 dias a partir de hoje]

Assinatura: _____________________

✓ Por que assinar

Assinatura ativa a parte do cérebro que se identifica com compromisso. Mais difícil quebrar com você mesmo quando há sua assinatura na parede.
